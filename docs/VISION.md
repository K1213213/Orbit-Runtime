# Orbit Agent Runtime · 架构愿景与宪章

> 版本：V1.0 · 定位：**Verifiable Agent Runtime —— 可复现 · 可证明 · 可核算**
> 本文是架构宪法：定义三条公理、五项架构升级、治理刻度盘、新机制准入清单。
> 与《UPGRADE_PLAN.md》（阻断项解决方案）、《architecture.md》（内核设计）配套阅读。

---

## 0. 定位与边界

**一句话**：Orbit 是**可验证的 Agent 运行时**——任何 Agent 行为都可被复现（重放链）、证明（隔离定理）、核算（资源账本）。

**不做（Anti-goals，防止护城河被稀释）**：
- 不自研工具生态（文件/Shell/Web 通过通道实现，MCP 生态通过 PAE 适配器复用）
- 不做 Agent 编排框架（那是 Harness / LangGraph 的主场，我们提供其下的运行时层）
- 不做模型训练与推理（模型是通道背后的服务）
- **不因功能速度妥协三公理**——这是唯一不可谈判的约束

---

## 1. 三条公理（Architecture Axioms）

公理是**不可协商**的架构底线；任何机制进入内核前必须证明不破坏公理。

### A1 · 可复现（Reproducible）
一次运行的所有非确定性决策与结果被完整记录；重放可在**零外部调用**下复现，输出逐字节一致，digest 链可检测任何篡改。
- **CI 验证**：`test/replay_compat.test.ts` —— 每个新机制的 record → replay 逐字节一致用例
- **边界**：确定性边界在**网关层**（`capabilityInvoke`），不是通道层；压缩器必须纯函数；限流与行为采集在重放模式旁路（详见 UPGRADE_PLAN A 节）

### A2 · 可证明（Provable）
故障影响 = 依赖图的**反向可达闭包**；隔离边界可形式化判定（隔离定理：互不依赖 ⇔ 互不波及）。
- **CI 验证**：图论单元测试（闭包/独立性/节点移除）+ 注册期能力闭包静态校验（声明的通道依赖 ⊆ 声明的能力）
- **边界**：逻辑层（图论闭包）+ 物理层（隔离域）双层协同，**图驱动域分配**

### A3 · 可核算（Accountable）
每次调用的成本、Token、延迟进入**统一资源账本**；预算策略（压缩 / 降级 / 停止）统一执行，且账本可重放核算。
- **CI 验证**：账本对账测试（重放核算与原始核算一致）
- **边界**：记账不参与调用序列（不破坏 A1）；账本事件进 TraceJournal

## 2. 五项架构升级

| # | 升级 | 内容 | 相对现有 |
|---|---|---|---|
| 2.1 | **事务化调用** | 每次能力调用 = 原子事务：`决策(校验/预算/路由) + 执行 + 结果 + 审计` | 从分散的 `fireChannelCall` 升级为网关统一事务 |
| 2.2 | **异构运行时网关** | PAE 隔离域 = 独立确定性域；域间交互为网关事务（跨域事件可对账） | 从"装进容器隔离"升级为"可对账的跨域一致性" |
| 2.3 | **双层隔离** | 逻辑层图论闭包 + 物理层隔离域；**影响域闭包大 → 自动升隔离级** | 从静态信任表升级为动态图驱动 |
| 2.4 | **资源账本** | 通道成本档案（已有）+ Token 预算（新增）= 统一账本 | 从分散的 `budgetPerCycle` 升级为确定性账本 |
| 2.5 | **三公理合一** | 重放链 + 隔离定理 + 预算账本 = **Verifiable Agent Runtime** | 从三个特性升级为三个公理 |

## 3. 分层可降级（Graceful Rigor）：治理是刻度盘，不是开关

核心原则：**底线强制（权限 / 熔断 / 审计永不动摇），增强可选（Schema / 压缩 / 保真度可协商）**。

### 3.1 四档治理模式（已落地 · v0.6.0）

> **状态标注（v0.6.0，W29）**：本表已落地为可切换的治理档位——`GovernanceProfile`
> 契约（`infra-common/types/governance.ts`）+ 宿主 `governanceProfile` 选项
> （`sandbox | standard | strict`，默认 `standard`）+ 机制注入（限流 / 熔断 / 压缩 /
> PAE 准入 / 轨迹持久化强制）。`standard` 解析为内核 v0.5.x 的数字**逐字一致**；
> 非默认档的档位哈希进入运行指纹，跨档重放报配置漂移（`RunFingerprintDriftError`）。
>
> **与原始表的偏差（落地时的工程裁决）**：
> ① **PAE 适配器**——Standard 实为**全部开启**（原始表"MCP + JS"）：
>   能力面完整是治理公理（见下方加粗行），砍掉已发布的 OpenAPI/Cordis 适配器违反
>   "为治理不砍功能"；安全性已由保真度协商 + 能力门 + 适配面哈希承担。Strict 仍关闭。
> ② **限流数字**——限流是**纯调用计数预算**（`RateLimiter`，无墙钟窗口，保证重放
>   确定性），"1000/min"落地为"每窗口 1000 次"：数量对档位生效，机制不引入时间。
> ③ **信任推定 / Schema 校验已落地**（W31）：信任推定 = PAE 隔离级上限
>    （`maxIsolationLevel`：strict 封顶 L1——防御性机制，strict 的 kind 关闭已覆盖外部
>    运行时）；Schema 校验 = 渐进式契约化（`schemaMode`：sandbox 可选 / standard 声明则
>    校验 / strict 强制声明，`validateArgsAgainstSchema` 纯函数 + 网关调用前校验，
>    详见 architecture.md §12）。
>    **轨迹签名已落地**（W30）：审计哈希链（HMAC-SHA256）——strict 档强制
>    `auditSigningKey`，每次启动验证整条链、被篡改即拒绝启动；`orbit audit` CLI 与
>    控制台审计页可随时验证（详见 architecture.md §11）。

| 维度 | Sandbox（开发） | Standard（默认） | Strict（合规） | Replay（调试/审计） |
|---|---|---|---|---|
| PAE 适配器 | 全部开启 | **全部开启**（落地裁决） | 关闭 | 全部（仅记录） |
| 信任推定 | 自动推定 L2 | 按来源 | 仅 L0 / L1 | 恢复记录值 |
| Schema 校验 | 可选 | 声明则校验 | 强制 | 声明则校验 |
| Token 压缩 | 关闭 | 开（纯函数） | 开（激进：阈值减半） | 开（纯函数） |
| 限流 | 宽松 1000/窗口 | 正常 100/窗口 | 严格 60/窗口 | **旁路**（恢复判定） |
| 行为采集 | 采集 + 提案 | 采集 | 采集 | **旁路** |
| 轨迹记录 | 内存 | 内存 + 落盘 | **强制落盘 + 签名链** | 全量 + 版本指纹 |
| 熔断阈值 | 5 次 / 冷却 30s | 5 次 / 冷却 10s | 3 次 / 冷却 5s（下限 1） | 恢复记录值 |

**能力面在 Sandbox 档是 100% 完整的**——治理强度随档位伸缩，不存在"为治理砍功能"。

### 3.2 六条机制（保证优势而不降低功能）

1. **能力协商（保真度标注）**：PAE 适配器完整映射异构能力并标注 `fidelity: full | reduced | lossy`，调用方**知情选择**，不静默丢功能。
2. **校验开销靠缓存**：注册期静态校验一次，运行时查 O(1) 权限位图；热点决策短 TTL 缓存。网关开销目标 ≤5%，靠工程优化而非削弱校验。
3. **确定性代价补偿**：限流与采集的"旁路"仅发生在 replay 模式（live/record 正常执行）；压缩器纯函数不意味弱压缩（内容哈希 / 长度阈值 / 语义摘要缓存）。
4. **渐进式契约化**：Schema 是**可选增强**（写了获得参数校验与文档生成，不写不阻塞）；权限 / 熔断 / 审计**永远强制**。
5. **能力覆盖靠复用**：工具能力走通道（File/Shell/HTTP），生态走 PAE（MCP），不自研——功能面追平，治理不降。
6. **性能预算**：网关转发开销 ≤5%、PAE 适配 L2 ≤15% / L3 ≤40%、故障影响宿主吞吐 ≤3%（详见升级方案性能评估体系）。

## 4. 能力覆盖矩阵（覆盖而不牺牲治理）

| 对标能力 | 覆盖方式 | 治理是否降级 |
|---|---|---|
| 文件 / Shell / Web 工具 | 通道实现（FileChannel / ShellChannel / HttpChannel） | 否（通道自带校验 / 熔断 / 审计） |
| MCP 生态 | PAE MCP 适配器（复用同一批 MCP 服务） | 否（转 Pact 后四重校验） |
| 子 Agent / workflow | 沙箱池 + 编排层（非内核） | 否（仍是网关事务） |
| 事件 / 插件生态 | Cordis 隔离实例（事件锁在域内，跨域为事务） | 否（且叠加图论可证明隔离） |
| OS 级沙箱 | 隔离域 L2 / L3 | 否（物理隔离 + 逻辑证明） |
| 模型接入 | OpenAICompatChannel（任意兼容端点） | 否（通道化，确定性契约） |

## 5. 新机制准入清单（Architecture Gate）

任何机制进入内核前，以下条目**全部通过**方可合并（纳入 PR 模板）：

- [ ] **A1**：`test/replay_compat.test.ts` 中该机制的 record → replay 逐字节一致用例通过
- [ ] **A1**：不含 `Math.random` / `Date.now` 的非确定性，或已通过 `RngSource` / `ClockSource` 注入
- [ ] **A1**：决策可记录进 `GatewayCallRecord.decision`（校验 / 预算 / 路由 / 限流 / 压缩）
- [ ] **A2**：若引入新依赖边，已更新 `ImpactDomainGraph` 并有对应图论用例
- [ ] **A3**：若涉及资源消耗，已计入资源账本并有对账用例
- [ ] **分层**：无反向依赖、无循环依赖，未绕过网关入口
- [ ] **测试**：全量测试不回归（当前基线 176 用例）+ 双 demo 冒烟通过
- [ ] **文档**：CHANGELOG 与本文（若涉及公理或档位变更）同步更新

## 7. 落地路径（增量升级，非重写）

沿用《UPGRADE_PLAN.md》B 段的三段式（增量加层 → 自底向上抽包 → pnpm workspace），功能顺序：

1. **Phase 1 · 网关与事务化**：`src/gateway/` 统一入口 + 决策记录（确定性边界上移，也是后续抽包骨架）
2. **Phase 2 · 资源账本**：Token + 成本统一，替代分散的 `budgetPerCycle`
3. **Phase 3 · PAE 接入**：MCP 适配器优先（价值密度最高）→ JS → Cordis 后置
4. **Phase 4 · 隔离与图驱动**：Worker 沙箱域 + 图驱动域分配
5. **Phase 5 · 持久化与接入层**：事务日志落盘 + REST 网关（演进自 bridge-server）

每一 Phase 结束：全量测试 + 双 demo + web 控制台回归通过，方可进入下一 Phase。
