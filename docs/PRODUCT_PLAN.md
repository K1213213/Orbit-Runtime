## 1. 一页纸摘要

**问题**：Agent 生产化的头号障碍不是模型能力，而是**不可复现性**——LLM 采样、随机数、时序任何一个变化，同样输入重跑两遍就是两个结果。开发者无法稳定复现 bug、无法证明"当时确实如此"、无法做可回归的测试。现有工具（LangSmith/Langfuse）只解决**可观测**（看记录），不解决**可复现**（重演）。

**方案**：Orbit 是 Agent 界的时间旅行调试器（Time-Travel Debugger）——记录一次运行的全部非确定性（模型响应/随机/时钟/调度序列），之后**零模型调用精确重放**，digest 链对账保证轨迹不可篡改。实测：978ms 真实运行 → 2ms 重放，输出逐字节一致。

**产品形态**（演进式）：确定性运行时内核（SDK）→ 重放调试 CLI/Web → 团队轨迹仓库 → 企业不可篡改审计平台。

**北极星指标**：**周活跃可复现调试会话（Weekly Reproducible Sessions）**——开发者用 Orbit 定位一个 Agent bug 的耗时从小时级降到秒级的次数。

**为什么是我们**：确定性重放 + 图论可证明隔离 + 成本治理三者在同一内核中组合，**市面无同款**。DSH 有工程能力无可复现性；Temporal 有确定性但非 Agent 专用；LangSmith 有观测无重放。

## 2. 市场与机会

### 2.1 市场背景
- Agent 开发已从"玩具"进入"生产"阶段，但生产化的最大瓶颈被反复验证为**可靠性/可观测性/可审计性**（行业报告共识：行为不可预测是 Agent 上生产的第一障碍）。
- 可观测赛道已拥挤（LangSmith、Langfuse、AgentOps…），**可复现赛道是空白**——"回看"与"重演"是两件事，现有工具全都在做前者。

### 2.2 机会窗口
| 信号 | 解读 |
|---|---|
| DSH 类运行时把"能跑"做完了，但无任何重放/审计能力 | 工程层已铺路，机制层缺位 |
| 金融/医疗/法律对 AI 行为的**可追溯性监管**逐年加严 | 审计型需求是刚需，愿付费 |
| Agent 测试（eval/regression）工具兴起但都基于"重跑"而非"重放" | 重放是更优的测试基座：零成本、确定性、可断言 |
| RR（Mozilla）、Time-Travel Debugging 在系统软件领域已被证明有巨大价值 | 同样的价值从未被搬到 Agent 运行时 |

### 2.3 市场规模（粗估）
- TAM：全球 Agent 开发工具市场（2026 估数十亿美元量级，CAGR ~40%+）
- SAM：其中"调试/可观测/测试"细分
- SOM（3 年目标）：开发者工具免费引流 + 企业审计版付费，目标数千开发者 + 数十家企业客户

## 3. 目标用户与画像

| 画像 | 场景 | 痛点 | 用 Orbit 得到 |
|---|---|---|---|
| **U1 Agent 应用开发者**（早期采用者） | 调试多步 Agent 流程、修 bug、写回归测试 | bug 不可复现，改一行重跑就变 | `orbit record` → 复现 → 秒级定位 |
| **U2 受监管行业工程师**（金融/医疗/法务） | Agent 做决策需留痕举证 | 无法证明"当时确实如此" | 不可篡改轨迹 + 可重放举证 |
| **U3 Agent 框架/平台厂商** | 把可复现性内嵌为自己的产品能力 | 自研重放成本高 | 嵌入式内核/SDK 授权 |

**早期策略**：先服务 U1（社区，传播快、反馈快），用 U1 的案例撬动 U2（付费），U3 作为长期渠道。

## 4. 竞品与差异化定位

| 竞品 | 解决 | 不解决 | 与 Orbit 的关系 |
|---|---|---|---|
| DeepSeek Harness / LangGraph / OpenAI Agents SDK | Agent 编排、工具执行 | 可复现、可证明、成本治理 | 互补：Orbit 可作其底层/插件 |
| LangSmith / Langfuse | 可观测、追踪、回看 | 重演（重跑结果不同） | 互补：可观测是记录，Orbit 是重放 |
| Temporal | 工作流确定性重放 | Agent 通道模型、LLM 语义 | 借鉴对象：确定性范式验证者 |
| Agent 测试框架（eval） | 指标评估 | 确定性基座（重跑有噪声） | Orbit 是其更好的基座 |

**定位主张（一句话）**：*"Agent 界的 RR / 时间旅行调试器 —— 别人记录，Orbit 重演。"*

**竞争壁垒（组合而非单点）**：
1. 确定性重放（先发 + 实现深度：digest 链对账防篡改）
2. 图论可证明隔离（故障影响 = 可达闭包，附定理）
3. 成本治理（预算护栏）
4. 三者同一内核、零依赖、可嵌入——对手复制单点容易，复制组合与生态位难

## 5. 产品定义

### 5.1 产品形态（三阶段演进）
- **阶段 A · SDK（0-6 个月）**：确定性运行时内核 + 真实 LLM 适配器 + 工具通道 + CLI（`record` / `replay` / `diff`）
- **阶段 B · 平台（6-12 个月）**：轨迹仓库 + Web 重放时间线（step-through/变量查看/分叉）+ 团队共享复现链接
- **阶段 C · 企业（12 个月+）**：哈希链不可篡改审计、合规报告、RBAC、私有化部署

### 5.2 MVP 范围（P0，6-8 周）—— 明确的取舍

**做**：
- OpenAI 兼容 LLM provider（落实 STOCHASTIC 种子注入契约）
- FileChannel / ShellChannel（真实工具，IO_BOUND + inject 重放语义）
- 轨迹持久化（JSONL，跨进程/跨机器重放）
- CLI 三件套：`orbit record <script>` / `orbit replay <trace>` / `orbit diff <a> <b>`
- 确定性契约开发者文档（"写一个可重放通道"指南）
- 安装即用：`npx orbit` 零配置体验

**明确不做**（防止失焦）：
- 多 Agent 协作、workflow 编排（那是 DSH 的主场，不做）
- 插件市场、UI 管理平台（阶段 B 再做）
- 非 LLM 相关的通用功能

**MVP 验收标准**：开发者用一个真实 OpenAI 兼容模型跑一个 5 步 Agent 流程 → record → 关掉网络重放 → 输出逐字节一致；篡改轨迹 → `orbit diff` 秒级定位。

### 5.3 开发者体验设计（差异化体验）
```
$ orbit record -m gpt-4o ./agent.js
  ▶ 5 steps · 3 model calls · 12.4s recorded  → trace saved: t-9f3a
$ orbit replay t-9f3a
  ⚡ 5 steps · 0 model calls · 38ms replayed  · output identical ✓
$ orbit diff t-9f3a t-9f3a-tampered
  ✗ digest chain broken at call #2 (llm-access.simulateChatRound)
```
核心体验：**一条命令让"玄学 bug"变成"必现 bug"**。

## 7. 商业模式

**开源内核（Apache-2.0）引流 + 分层商业化**：

| 层 | 形态 | 定价思路 |
|---|---|---|
| 内核 + CLI | 开源免费 | 获客与生态 |
| 团队平台（轨迹仓库/协作） | SaaS 免费额度 + 付费容量 | 自助订阅 |
| 企业审计版 | 私有化 + 不可篡改审计 + 合规报告 + 支持 | 年度订阅（按席位/按调用量） |
| 厂商授权 | 内核嵌入 SDK 授权 | 定制合同 |

**关键商业判断**：审计合规（U2）是当前最可能产生付费的切入口——"可证明 Agent 当时确实这么做"在金融/医疗监管下是刚需，且 Orbit 的 digest 链防篡改是现成答案（哈希链方案此前已设计）。

## 9. 风险与对策

| 风险 | 概率 | 对策 |
|---|---|---|
| **市场过窄**：可复现性是不是足够大的入口 | 中 | 定位为"Agent 基建入口"：可复现先行，可观测/审计/治理全家桶后续覆盖（图论隔离、成本治理已在同一内核） |
| **DSH 等大厂跟进重放** | 中 | 先发 + 论文/标准话语权 + 组合壁垒（重放×审计×图论）+ 社区锁定；被抄单点，抄不走生态位 |
| **绑定单一模型商** | 中 | OpenAI 兼容层 + 多 provider 适配器（DeepSeek/Anthropic/本地模型） |
| **开发者抗拒"换运行时"** | 高 | 双模式：完整运行时 + **仅重放机制**的轻量 SDK（可嵌进任何框架，不动对方运行时） |
| **调试场景被 eval 工具吞并** | 低 | 反向：Orbit 是 eval 的确定性基座，做"eval 的重放底座"而非与 eval 竞争 |
